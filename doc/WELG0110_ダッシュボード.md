# 画面設計書: ダッシュボード

| 項目 | 内容 |
| --- | --- |
| ファイル名 | `WELG0110_ダッシュボード.md` |
| 画面ID | WELG0110 |
| 対応 | `管理画面モック.pdf` 1ページ |
| 画面名 | ダッシュボード |
| 技術 | React 18、関数コンポーネント、Hooks、Next.js 14（App Router）、Redux、TypeScript |

この文書だけで、ダッシュボードの見た目とデータ描画を実装できること。ボタン押下後の業務処理は対象外。

この画面の色、余白、文字サイズ、太さは、この設計書の数値を使う。共通部品に付け替えるときは `doc/共通部品.md` に従い、部品とこの画面の両方で指定しているプロパティは、そこに書いた CSS 変数へこの設計書の数値を代入する。部品が指定していない幅や位置は、この設計書の数値を通常の CSS で書く。

## 印の意味

- 【不明】PDFにも別要件にも確定値がない。実装で文言や動作を足さない。
- 【仮】画面を置くためにこちらの設計で決めた値。PDFには無い。

## 作る範囲

- 右側のダッシュボード本文を表示する。左側の紺領域は、この画面の page では描画しない。
- 指標カード、コース別進捗、公開待ちレッスンは、渡された配列の件数だけ描画する。
- 初期表示用のサンプルデータは Redux の初期 state に置く。

## 作らない範囲

- 右側のボタンとログアウトのクリック後の処理。メニュー5項目以外の画面切り替えは作らない。
- 左側を、この画面のコンポーネントの中で描き直すこと。
- API 通信、保存、メニュー5項目以外の画面遷移、権限による出し分け。
- 進捗率や人数の計算。表示する数はデータとして受け取る。

## レイアウト

画面全体は横並びで、左がサイドメニュー、右が本文。この画面が描画するのは右だけ。左は「左側の紺領域」が親レイアウトで描画する。背景は薄いグレー、本文内の塊は白カード。色、余白、文字サイズ、角丸は「見た目の暫定値」。

| 要素 | 見た目 |
| --- | --- |
| 画面背景 | 薄いグレー |
| サイドメニュー | 濃い紺。幅は見た目の暫定値 |
| 選択中メニュー | 青背景、白文字 |
| 未選択メニュー | 白に近い文字、背景なし |
| カード | 白。枠線は付けない。外側の影は見た目の暫定値 |
| 主要数値 | 大きい。25px のまま太字。% も含む |
| 進捗バーの塗り | 青。トラックは薄い青 |
| サンプルデータ | 薄い黄色の丸いバッジ |
| 編集ボタン | 白背景、枠線、小さめ |

```text
+----------------+----------------------------------------------+
| 管理コンソール | ダッシュボード                    [サンプルデータ] |
| サブタイトル   | 説明文                                        |
|                | [指標][指標][指標][指標]                      |
| メニュー       | [コース別の学習進捗    ] [公開待ちのレッスン] |
|                |                                               |
| 管理者情報     |                                               |
| ログアウト     |                                               |
+----------------+----------------------------------------------+
```

指標は、画面幅 1080px で4枚のとき1行にし、折り返さない。ここでの画面幅は、ブラウザの表示領域の幅とする。

左右余白は 31px、サイドバーは 180px。本文の内側は 838px。指標4枚、間隔 14px が3つのとき、カード幅は 199px。この組み合わせで横幅は 1080px になる。

画面幅が 1080px より広いときは、指標も下段も幅を増やさない。余った幅は本文の右側に空ける。

画面幅が 960px 以上のときは、指標は1行のままにする。間隔 14px は固定し、カード幅は内側の余りを枚数で等分する。割り切れない端数は、その段の右端のカードに足す。1080px で5枚なら、幅は 156px が4枚、右端だけ 158px。計算は (838 - 14×4) = 782、782 を5で割った余り 2px を右端に足す。

画面幅が 960px 未満では指標を2列にする。横の間隔も縦の間隔も 14px。カード幅は (内側 - 14px) / 2。端数は右のカードに足す。2列で余り1枚のときは左に置き、幅は同じ列の1枚と同じにする。画面幅が 560px 未満では指標を1列にし、カード幅は本文の内側いっぱいにする。縦の間隔は 14px【仮】。横の 14px を縦にも使う。

下段は、画面幅 960px 以上では横並びにする。間隔 20px。画面幅 1080px の暫定は、左 491px、右 327px。960px 以上で 1080px 未満のときは、間隔 20px を残し、491:327 の比で両方を縮める。割り切れない端数は右のカードに足す。1080px より広いときは、この幅のままにする。画面幅が 1080px 以上でも、本文の内側が 838px 未満のときは、同じ比で縮める。スクロールバーで内側が狭くなる場合である。画面幅 960px 未満では縦に積み、間隔 20px、幅は本文の内側いっぱいにする。

本文の下余白は 31px【仮】。左右の 31px と同じ。

本文の左右は、左がコース別進捗、右が公開待ち。幅は見た目の暫定値。右上の「サンプルデータ」は、この画面の `showSampleDataBadge` が `true` のときだけ出す。消す条件は【不明】。バッジは、見出しと説明の塊の上下中央に置き、その行の右端に寄せる。左右の内側は 10px【仮】。見出し側との最小間隔は 16px【仮】。

## 見た目の暫定値

PDF 1ページ目の画像と、文字の位置・サイズから測った値。実装で合わせるための暫定であり、指定値ではない。1px 単位に丸めている。小数だった実測は、表の実測列に残す。

基準は、モック画像の 1080×825 をそのまま px とみなす。これより狭い画面での折り返しは、このページからは測れない。フォントファミリー名は文字レイヤーから取れていない。実装では、画面全体の `Arial, Helvetica, sans-serif` を継承する。ボタンも同じ書体を継承する。

太さは文字レイヤーから取れていない。次の文字だけ、フォントサイズはそのままにして `font-weight: bold` にする。

- 画面見出し「ダッシュボード」（`title`）
- 「サンプルデータ」
- カード見出し「コース別の学習進捗」「公開待ちのレッスン」
- 編集ボタンの文字
- コース名（`courseName`。サンプルでは「日本語入門 N5」など。平均進捗とパーセントは含めない）
- 公開待ちのレッスン名（`title`。サンプルでは「第3課 買い物のあいさつ」など。補足は含めない）
- 指標の数値（`value` を表示した文字列。サンプルでは「1,248」「386」「46」「74%」。% も同じ太字。ラベルと注釈は含めない）

それ以外は通常の太さ（`font-weight: normal`）にする。行高は、その文字の暫定フォントサイズと同じ値にする。

画面のルートは `color-scheme: light`【仮】。背景と文字色は、この節の色を使う。OS のダーク表示で置き換えない。

## 左側の紺領域

WELG0110、WELG0120、WELG0130、WELG0140、WELG0150 の左側は、同じ1つの部品にする。各画面の page の中には置かない。画面が変わっても、この部品はアンマウントせず、描き直さない。

メニュー5項目を押すと、`useRouter()` の `push` で下の仮ルートへ移動する。パスは `/dashboard` のように、先頭が `/` のパスだけにする。`http://localhost` やポート番号は付けない。移動後の選択中は、今のパスから決める。ログアウトは移動しない。

ログイン（WELG0010）はこの領域の外に置く。左側は出さない。

## ダッシュボード固有の型

日付は `src/features/calendar-date/calendarDate.ts` の `CalendarDate`。`year`、`month`、`day` は数。`Date` にはしない。公開待ちの更新日は `formatMonthDay` で、年を出さず `10/12` のように 2桁の月と 2桁の日を `/` でつないで出す。画面に年が無かったので、年は【仮】`2026`。

```ts

  id: string;
  label: string;
  value: number;
  valueKind: MetricValueKind;
  note: string;
};

  id: string;
  courseName: string;
  progressRate: number;
  lessonCount: number;
  activeLearnerCount: number;

  title: string;

  courseProgresses: CourseProgress[];

```

数値の計算式は持たない。`value` は数。`valueKind` が `"count"` のときは 3 桁ごとにカンマを付けて出す。`"percent"` のときは、同じ桁区切りのあとに `%` を付ける。平均正答率の `74` は `74%` として出す。割合を `0.74` にはしない。`progressRate` は 0 以上 100 以下の数としてバー幅に使う。範囲外のときの扱いは【不明】。範囲外でも計算で補正せず、渡された数をそのまま幅のパーセントに使う。

## 受け入れ条件

- `/dashboard` を開くと、親レイアウトの左側と、右側の見出し、説明、サンプルデータバッジが見える。選択中メニューは WELG0110。選択中の画面IDは slice に無く、パスから決まる。
- `DashboardView` は `AdminShell` を描画しない。左側は `(console)/layout.tsx` に1つだけある。
- `dashboard` の配列を増減しても、`AdminShell` は再レンダーしない。
- 指標、コース進捗、公開待ちが初期データの件数と内容で見える。
- `metrics` を5件にするとカードが5枚になる。画面幅 1080px では1行のまま、間隔 14px、幅は 156px が4枚、右端だけ 158px。0件にするとカードが消える。
- `courseProgresses` と `pendingLessons` も同じように増減する。
- 各コースは同じセットで、左にコース名、右に「平均進捗」とパーセント、その下にバー、その下にレッスン数が出る。バーの塗り幅が `progressRate` と一致する。

- 右側がビューポートより短いとき、ログアウトは画面の下端から 30px。右側が長いとき、左の紺は右側と同じ高さまで伸び、ログアウトはその下端から 30px。
